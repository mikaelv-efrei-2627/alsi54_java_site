1 Héritage

1.1 Introduction

  • L’héritage est mis en œuvre par la construction de classes dérivées
  • Il représente la relation : « **est un » ou « est une sorte de »

1.2 Vocabulaire

  • La classe dont on dérive est dite : classe de base, mère, parente
    • Animal est la classe de base
  • Les classes obtenues par dérivation sont dites : classes dérivées, filles, sous classes
    • Chat, Chien et Oiseau sont des classes dérivées

1.3 Intérêt

  • Permet de réutiliser les attributs et les méthodes d’une autre classe
  • Vision descendante : la possibilité de reprendre ce qui a été déjà fait
  • Vision ascendante : la possibilité de regrouper en un seul endroit ce qui est commun à plusieurs

1.4 Syntaxe

  • mot clé : extends
  • Les constructeurs ne sont pas hérités
  • Les mot-clés de visibilité peuvent restreindre l’accès
  • Appel au constructeur de la classe héritée via super()
  • pas d’héritage multiple:
    • chaque classe a une et une seule classe mère

1.5 Syntaxe - Classe mère

class Personne {
    private String nom;
    private int age;

    // Constructeur de la classe mère
    public Personne(String nom, int age) {
        this.nom = nom;
        this.age = age;
    }

    public void afficherInfo() {
        System.out.println("Nom: " + nom + ", Âge: " + age);
    }
}

1.6 Syntaxe - Classe fille

class Etudiant extends Personne {
    private String filiere;

    // Constructeur de la classe fille
    public Etudiant(String nom, int age, String filiere) {
        // Super pour appeler le constructeur Personne
        super(nom, age);
        this.filiere = filiere;
    }

    public String getFiliere() {
        return filiere;
    }

    // Redéfinition de la méthode afficherInfo
    @Override
    public void afficherInfo() {
        super.afficherInfo();
        System.out.println("Filière: " + filiere);
    }
}

1.8 Overriding (redéfinition)

Lorsque la classe fille définit une méthode dont la signature est compatible avec celle d’une méthode de la classe mère.

signature = Nom + types des paramètres + type de retour

Tip

Une bonne pratique est d’ajouter l’annotation @Override sur la méthode redéfinie. Ainsi, si la méthode mère est modifiée, le compilateur signalera que la méthode redéfinie ne redéfinit rien.

1.9 Héritage - restrictions

  • Une classe fille ne peut pas accéder aux attributs et aux méthodes private de sa classe mère.
  • Une méthode ayant le modificateur final dans la classe mère ne peut pas être redéfinie dans la classe fille.
  • Une classe mère ayant le modificateur final ne peut pas être étendue.

1.10 Overloading (surcharge)

  • La surcharge est le fait de définir une méthode dans une même classe ou une sous-classe qui:
    • a le même nom
    • mais qui des paramètres de types différents, ou un nombre de paramètres différent
  • Les 2 méthodes ont une signature incompatible

Important

Ne pas confondre overriding (redéfinition, signatures compatibles) et overloading (surcharge, signatures incompatibles)

1.11 Overloading - Exemple

class Etudiant extends Personne {
    // ...

    // Redéfinition (override) de la méthode afficherInfo
    @Override
    public void afficherInfo() {
        super.afficherInfo();
        System.out.println("Filière: " + filiere);
    }
    
    // Surcharge (overload) de la méthode afficherInfo
    public void afficherInfo(String separateur) {
        super.afficherInfo();
        System.out.println(separateur);
        System.out.println("Filière: " + filiere);
    }
}

2 Polymorphisme

Poly = plusieurs, morphe = formes

Le polymorphisme est un concept clé de la programmation orientée objet (POO) qui permet à des objets de différents types de répondre à la même interface ou méthode, tout en implémentant des comportements spécifiques selon leur propre type.

2.1 Polymorphisme statique

Il est implémenté en utilisant la surcharge et est déterminé au moment de la compilation.

public class Calculatrice {
    // Surcharge de méthodes
    public int addition(int a, int b) {
        return a + b;
    }

    public double addition(double a, double b) {
        return a + b;
    }
}
var calc = new Calculatrice();
// La méthode prenant les int est appelée
calc.addition(2, 2);
// La méthode prenant les double est appelée
calc.addition(2.0, 2.0);

2.2 Polymorphisme dynamique - UpCast

dynamique = Déterminé lors de l’exécution.

UpCast = Un objet de classe fille est considéré comme une instance de la classe mère. Il est implicite.

Personne p = new Etudiant("Alice", 20);
// on peut appeler toutes les méthodes de la classe Personne
// la méthode appelée est celle qui a été redéfinie dans la classe Etudiant
p.afficherInfo();

2.3 Polymorphisme dynamique - DownCast

DownCast = Un objet est considéré comme étant d’une classe fille de sa classe de déclaration. Il est explicite.

Personne p = new Etudiant("Alice", 20, "ING1");
String s;
if (p instanceof Etudiant)
    s = ((Etudiant)p).getFiliere();
else
    s = "";

2.4 DownCast - pattern matching

Depuis Java 14, le pattern matching a amélioré la syntaxe “instanceof” + casting :

Personne p = new Etudiant("Alice", 20, "ING1");
String s;

if (p instanceof Etudiant e)
    // On nomme la classe Etudiant une seule fois.
    // Cela évite d'avoir à caster, qui pouvait être une source de bug
    s = e.getFiliere();
else 
    s = "";

2.5 DownCast - switch

Depuis Java 17, le pattern matching a été étendu au switch :

Personne p = new Etudiant("Alice", 20, "ING1");
String s = switch (p) {
    case Etudiant e -> e.getFiliere();
    default -> "";
}

3 Classe abstraite

  • Une classe est dite abstraite si une ou plusieurs méthodes ne sont pas implémentées.
  • Les méthodes non implémentées sont aussi appelée méthodes abstraites
  • Caractéristiques d’une méthode abstraite :
    • Sans implémentation
    • L’implémentation se fait lors de l’héritage
  • Caractéristiques d’une classe abstraite :
    • Au moins une méthode est abstraite
    • Impossible de l’instancier directement. Il faut définir une sous classe qui implémente les méthodes abstraites

3.1 Syntaxe

Mot-clé abstract devant une classe ou une méthode.

Forme.java
public abstract class Forme {
    private String nom;

    public String getNom() {
        return nom;
    }

    // les sous-classes doivent implémenter cette méthode
    public abstract double surface();
}
Rectangle.java
public class Rectangle extends Forme {
    private double x, y;

    public Rectangle(double x, double y) {
        this.x = x;
        this.y = y;
    }

    @Override
    public double surface() {
        return x * y;
    }
}
Cercle.java
public class Cercle extends Forme {
    private double rayon;

    public Cercle(double rayon) {
        this.rayon = rayon;
    }

    @Override
    public double surface() {
        return Math.PI * rayon * rayon;
    }
}

3.2 Syntaxe - exemple

public class Main {
    public static void main(String[] args) {
        List<Forme> formes = Arrays.asList(
                new Cercle(2),
                new Cercle(3),
                new Rectangle(4, 5),
                new Cercle(7),
                new Rectangle(1, 1));

        var surfaceTotale = 0.0;
        for (Forme forme : formes) {
            // polymorphisme: la méthode "surface" appelée
            // dépend du type de l'objet forme
            surfaceTotale += forme.surface();
        }
    }
}

3.3 Utilisation

Une classe abstraite sert de modèle pour créer des classes concrètes qui en hériteront.

Une classe abstraite définit une implémentation partielle:

  • Les méthodes concrètes ont des instructions
  • Les méthodes abstraites n’en ont pas

Les classes concrètes qui en hériteront doivent compléter cette implémentation.

4 Interfaces

Une interface:

  • est une classe qui ne possède que des méthodes abstraites et des constantes (attributs final)
  • peut aussi déclarer des implémentations par default (voir plus loin)
  • se déclare avec le mot-clé interface
  • n’implémente aucune méthode
  • décrit un ensemble de méthodes en fournissant uniquement leur signature
  • peut être considérée comme une classe 100 % abstraite

4.1 Syntaxe - déclaration

public interface Carnivore {
    void manger(Animal animal);
}
public interface Herbivore {
    void manger(Vegetal vegetal);
}
  • Il n’est pas nécessaire de préfixer les méthodes avec abstract
  • Toutes les méthodes sont par défaut public

4.2 Syntaxe - sous-classes

  • Une interface peut étendre une ou plusieurs autres interfaces avec extends
  • Une classe signale l’interface qu’elle implémente grâce au mot- clé implements
  • Une classe peut étendre (extends) une et une seule classe mais implémenter (implements) une ou plusieurs interfaces

4.3 Syntaxe - sous-classes

public class Humain implements Carnivore, Herbivore {

    @Override
    public void manger(Animal animal) {
        // ...
    }

    @Override
    public void manger(Vegetal vegetal) {
        // ...
    }
}

Nous pouvons aussi regrouper les 2 interfaces dans une nouvelle interface :

public interface Omnivore extends Carnivore, Herbivore {

}

public class Humain extends Omnivore {
    // ...
}

4.4 Interface Comparable

  • L’interface Comparable, nécessite l’implémentation de la méthode compareTo
public interface Comparable<T> {
   /** 
    * Doit retourner:
    * - un entier négatif quand x < y
    * - un entier positif quand x > y
    * - 0 quand x.equals(y)
    */
    public int compareTo(T o);
}
  • L’interface Comparable est destinée à la comparaison d’objets de la même classe

4.5 Comparable - exemple

public class Personne implements Comparable<Personne> {
    private String nom;
    private int age;

    // ...

    @Override
    public int compareTo(Personne o) {
        // par ordre alphabétique du nom
        return this.nom.compareTo(o.nom);
    }

    // Il est fortement recommandé de redéfinir equals lorsqu'on implémente compareTo
    // on doit toujours avoir (x.compareTo(y)==0) == (x.equals(y))
    @Override
    public boolean equals(Object o) {
        // ... 
    }

Certaines méthodes du JDK comme Collections.sort utilisent Comparable:

import java.util.Arrays;
import java.util.Collections;

var personnes = Arrays.asList(new Personne("Bob", 20), new Personne("Alice", 22));
// Trie les personnes par ordre alphabétique
Collections.sort(personnes);

4.6 Sealed interface

  • Depuis Java 17, nous pouvons restreindre quelles classes peuvent implémenter une interface.
  • Pour cela, on utilise le mot-clé sealed et on spécifie les sous-types autorisés avec permits
public sealed interface Forme permits Cercle, Rectangle, Triangle {
    double surface();
}

4.7 Sealed - sous-classes

  • Les sous-classes doivent avoir le mot-clé suivant :
    • final : La sous-classe ne peut pas être sous-classée davantage.
    • sealed: La sous-classe peut restreindre encore plus l’héritage en spécifiant à son tour des sous-types autorisés.
    • non-sealed: la sous-classe peut être sous-classée sans restriction

4.8 Sealed - intérêt

  • vérification à la compilation. Dans des expressions switch, permet de s’assurer que tous les cas sont couverts
  • Documentation claire : Les sealed interfaces définissent explicitement quels sont les sous-types possibles, ce qui rend l’intention du développeur plus claire.

4.9 default methods

  • Les méthodes par défaut (ou default methods) ont été introduites avec Java 8.
  • Elles permettent aux interfaces d’avoir des implémentations de méthodes concrètes
public interface Vehicule {
    // Méthode abstraite
    void demarrer();

    // Méthode par défaut
    default void klaxonner() {
        System.out.println("Tut-tut !");
    }
}

4.10 default - utilisation

  • Evolution d’une interface sans casser les implémentations existantes
  • Réutilisation de code

Différence avec abstract class :

  • une classe abstraite peut avoir des attributs

4.11 default - conflits

Des conflits peuvent apparaître.

public interface InterfaceA {
    default void afficher() {
        System.out.println("Interface A");
    }
}

public interface InterfaceB {
    default void afficher() {
        System.out.println("Interface B");
    }
}

public class MaClasse implements InterfaceA, InterfaceB {
    // Résolution du conflit en redéfinissant la méthode
    @Override
    public void afficher() {
        System.out.println("MaClasse résout le conflit");
    }
}

Il faut les résoudre en redéfinissant la méthode.

4.12 default - super

  • vous pouvez appeler l’une ou l’autre interface avec Interface.super.method()
public class MaClasse implements InterfaceA, InterfaceB {
    // Résolution du conflit en redéfinissant la méthode
    @Override
    public void afficher() {
        InterfaceA.super.afficher();
    }
}
