1.1 Exercice : Calculatrice

Écrire un programme qui calcule une opération sur deux entiers saisis par l’utilisateur.

Le programme doit :

  1. Demander deux entiers a et b au clavier. (utiliser Scanner)
  2. Demander une opération parmi *, -, +, /
  3. Calculer le résultat et l’afficher
  4. Gérer les erreurs suivantes :
    • Division par zéro (exception ArithmeticException),
    • Saisie non numérique (exception NumberFormatException),
    • Lever une exception personnalisée NegativeNumberException si l’un des nombres est négatif.

2 Test unitaires

Dans IntelliJ, vous devez configurer votre projet pour qu’il utilise un autre répertoire pour les tests:

  • créer un répertoire test à la racine du projet
  • aller dans File -> Project Structure
  • Modules -> Sources
  • Choisir le répertoire test et sélectionner “Mark as”: Tests

2.1 Exercice : Tests sur la calculatrice

Écrivez des tests unitaires pour la méthode Calculator.calculateInt. Ils doivent couvrir le “happy path” et les différents “unhappy paths”.

  • Pour créer CalculatorTest, vous pouvez sélectionner la classe Calculator, puis utiliser le menu “Code” -> “Generate” -> Test
  • La nouvelle classe aura une erreur dans les imports. Déplacez le curseur sur l’erreur, puis alt-enter. Choisissez “Add Junit5.8.1 to classpath”

2.2 Exercice : Calculatrice RPN

Notre calculatrice n’est pas très évoluée, elle ne gère pas les expressions complexes. En utilisant la technique TDD, vous allez implémenter une calculatrice RPN (Reverse Polish Notation).

Une calculatrice RPN utilise une pile LIFO pour stocker les opérandes (entiers).

  • Lorsqu’on entre un nombre, la calculatrice l’empile.
  • Lorsqu’on entre un opérateur (+, -, /, *, …), la calculatrice :
    • dépile les opérandes
    • effectue le calcul
    • empile le résultat

Cela permet de calculer des expressions complexes sans utiliser de parenthèses. C’est le mode opératoire de la calculatrice HP48. Exemple d’utilisation du programme pour calculer 16 / (3 + 1):

Enter a number or an operation: 16
-----
16
-----
Enter a number or an operation: 3
-----
16
3
-----
Enter a number or an operation: 1
-----
16
3
1
-----
Enter a number or an operation: +
-----
16
4
-----
Enter a number or an operation: /
-----
4
-----
Enter a number or an operation: exit
  1. Créez ce squelette d’implémentation :
package rpn;

import java.util.Scanner;
import java.util.Stack;

public class RpnCalculator {
    private final Stack<Integer> stack = new Stack<>();

    public void evaluate(String input) {
        // TODO indice: utiliser switch, stack.push(...), stack.pop()
    }
    
    public Collection<Integer> getStack() {
        return Collections.unmodifiableCollection(stack);
    }

    public void printStack() {
        for (Integer element: stack) {
            System.out.println(element);
        }
    }


    public static void main(String[] args) {
        Scanner scanner = new Scanner(System.in);
        final var calc = new RpnCalculator();
        String input = "";
        while (!input.equals("exit")) {
            System.out.print("Enter a number, an operation, or exit: ");
            input = scanner.nextLine();

            calc.evaluate(input);

            System.out.println("-----");
            calc.printStack();
            System.out.println("-----");
        }
    }
}
  1. Créez un test unitaire pour tester la méthode evaluate sur un cas simple, par example 2 2 +. Le test va échouer (RED).
  2. Implémentez evaluate, mais n’implémentez pas plus que nécéssaire pour faire passer le test. Le test va passer (GREEN).
  3. refactorisez le code si besoin
  4. recommencez le cycle red-green-refactor pour tester et implémenter :
    • les autres opérateurs -, *, /
    • les cas plus complexes
    • les cas limites (pile vide, taille maximale de pile atteinte)
    • les cas d’erreur : les opérandes doivent être des entiers, division par zéro, …

2.3 Exercice : Bowling Game Kata

Implémentez le Bowling Game Kata en suivant pas à pas la présentation.

  • vous allez implémenter une fonction qui calcule le score d’un jeu de bowling, en utilisant la technique TDD.
  • il est conseillé de retaper le code pour bien mémoriser la technique et se familiariser avec l’auto-complétion d’IntelliJ
  • le premier test testGutterGame envoie toutes les boules dans la rigole (gutter)
  • on implémente ensuite le code qui satisfait le test
  • le 2ème test testAllOnes enlève une seule quille à chaque essai (roll)
  • on implémente ensuite le code qui satisfait le 2ème test
  • …
  • lorsque les tests passent, on peut “refactor” le code pour le rendre plus lisible et plus maintenable, avant d’écrire plus de tests
