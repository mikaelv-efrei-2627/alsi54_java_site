1 Encapsulation et Visibilité

1.1 Encapsulation

  • L’encapsulation est le principe qui consiste à limiter la visibilité de la structure d’une classe
  • Cette restriction peut s’appliquer aux :
    • attributs
    • méthodes
  • encapsulation totale: masquer complètement les attributs aux éléments en dehors de la classe

1.2 Visibilité

  • Cacher la complexité de l’objet
  • Restreint l’accès à certaines méthodes et attributs
  • Permet la modification de certaines méthodes sans perturber l’utilisateur
  • Définition de droits d’accès avec les mots clés public, protected, private ou rien du tout (modificateur par défaut).

1.3 Les modificateurs

Devant une classe, un attribut ou une méthode, nous pouvons utiliser les modificateurs suivants:

  • private: visibilité limitée à la classe
  • protected : visibilité limitée aux sous-classes et aux classes du même package.
  • public : visibilité pour toutes les classes et tous les packages
  • néant : visibilité limitée aux membres d’un même package

1.4 Les modificateurs: résumé

Modifier Classe Package Sous-classe Autres
public O O O O
protected O O O N
néant O O N N
private O N N N

En pratique:

  • Il est rare d’utiliser le modificateur par défaut.
  • Pour les attributs, il est déconseillé d’utiliser public pour respecter le principe d’encapsulation

1.5 Exemple: Point cartésien

public class Point {
    // attributs privés. 
    // Leur accès est contrôlé avec les getter/setters
    private double x;
    private double y;

    public Point(double x, double y) {
        this.x = x;
        this.y = y;
    }

    public double getX() {
        return x;
    }

    protected void setX(double x) {
        this.x = x;
    }

    public double getY() {
        return y;
    }

    protected void setY(double x) {
        this.x = x;
    }

    /* Fait pivoter le point d'un angle donné en radians */
    public void rotate(double angle) {
        // Calcul des coordonnées polaires à partir des coordonnées cartésiennes
        double r = Math.sqrt(x * x + y * y);
        double theta = Math.atan2(y, x);

        // Mise à jour de l'angle
        theta += angle;

        // Recalcul des coordonnées cartésiennes après rotation
        this.x = r * Math.cos(theta);
        this.y = r * Math.sin(theta);
    }
}

1.6 Exemple: Point polaire

public class Point {
    // Coordonnées polaires
    private double r;     // distance radiale
    private double theta; // angle en radians

    // Constructeur prenant des coordonnées cartésiennes
    public Point(double x, double y) {
        this.r = Math.sqrt(x * x + y * y);
        this.theta = Math.atan2(y, x);
    }

    public double getX() {
        return r * Math.cos(theta);
    }

    public double getY() {
        return r * Math.sin(theta);
    }

    /* Fait pivoter le point d'un angle donné en radians */
    public void rotate(double angle) {
        this.theta += angle;
    }
}

Les méthodes publiques de la classe restent identiques: on utilise toujours les coordonnées cartésiennes.

C’est le principe d’encapsulation: la structure interne de la classe n’est pas visible de l’extérieur.

1.7 getters et setters

Afin de contrôler l’accès aux attributs d’une classe, il est fréquent de déclarer des accesseurs.

  • Un accesseur en lecture sera nommé get + nom de l’attribut, ou pour les boolean: is+ nom de l’attribut
  • Un accesseur en écriture sera nommé set + nom de l’attribut
private String attribut;

public String getAttribut() {
    return attribut;
}

protected void setAttribut(String att) {
    this.attribut = att;
}

1.8 getters et setters: bonnes pratiques

  • ne pas implémenter systématiquement
    • cela expose la structure interne, en particulier si le setter est public
  • implémenter si nécessaire
    • accès contrôlé avec visibilité
    • un setter peut vérifier qu’une valeur est valide
    • un getter peut valider ou transformer une valeur avant de la retourner
    • pour exposer certaines propriétés à d’autres classes
  • getters/setters intelligents
    • méthodes d’accès métier qui encapsulent la logique d’accès
    • setSalary => augmenterSalaire(double pourcentage)
  • utiliser les propriétés immuables (voir ci-dessous)

2 Attributs et Variables “final”

2.1 Final

Le mot-clé final peut être placé:

  • devant un attribut
  • devant une variable
  • devant une méthode ou une définition de classe
    • interdit la redéfinition ou les sous-classes, voir plus loin

2.2 Attribut final

Un attribut final est immuable (en: immutable). Il est initialisé dans le constructeur et ne peut pas être modifié par la suite.

public class Point {
    public final int x;
    public final int y;

    Point(int x, int y) {
        this.x = x;
        this.y = y;
    }
}

// ...
Point p = new Point(2, 3);
p.x = 5; // erreur de compilation

2.3 pourquoi utiliser l’immuabilité ?

Un objet immuable peut être passé en argument à de multiples méthodes en étant certain de son état au retour.

  • lecture du code plus aisée, permet de raisonner sur le code
  • partage de l’objet entre plusieurs Threads

Modifier un objet immuable = renvoyer une nouvelle instance modifiée

L’immuabilité est un concept clé de la programmation fonctionnelle.

2.4 Exemples de classes immuables

  • java.lang.String
  • java.time.LocalDate
  • java.util.UUID

2.5 Records

Depuis Java 14, nous pouvons utiliser les classes record.

  • Tous leurs attributs sont immuables.
  • des méthodes sont générées automatiquement: accesseurs, toString, equals, hashCode
public record Point (int x, int y) {}
var p = new Point(2, 3);
p.x(); // accesseur
p.toString(); 
p.equals(new Point(2, 3));

2.6 Variable immuables

final peut être utilisé pour une variable locale

final int min;
min = Math.min(x, y);
i = 3; // erreur de compilation

final var s = "hello";
s = "world"; // erreur de compilation
  • Bonne pratique: marquer les variables qui ne changent pas avec final.
  • Cela permet au lecteur de raisonner et se dire “ok, cette variable ne changera jamais”.

Un développeur passe beaucoup plus de temps à lire du code qu’à en écrire. Un code facile à lire et comprendre sera plus facile à maintenir et faire évoluer.

En Scala et Kotlin, le mot-clé val permet de déclarer une variable immuable. En Java, il faut ajouter le mot final, ce qui est plus verbeux. Les développeurs Java ont par conséquence moins tendance à appliquer cette bonne pratique.

Solution: utiliser Lombok val

3 Membres de classe

  • Les attributs et méthodes “standard” vus jusque là sont propres à un objet = instance de la classe
  • Le mot-clé static devant un attribut ou une méthode déclare un membre qui est commun à toutes les instances de la classe

3.1 Variables de classe

public class Car {
    private String name;
    private String engine;
    
    private static int numberOfCars;
    
    public Car(String name, String engine) {
        this.name = name;
        this.engine = engine;
        numberOfCars++;
    }

    // getters et setters
}

A chaque instanciation de la classe Car avec new Car(...), la variable numberOfCars est incrémentée.

3.2 Constantes

  • Si l’on combine final et static, on obtient une variable de classe qui ne peut pas être modifiée
  • C’est donc une constante !
public class Person {
    private int age;

    private static final int AGE_MAJEUR = 18;

    // constructeurs, getters et setters

    public boolean isMajeur() {
        return age >= AGE_MAJEUR;
    }
}
  • Convention: les constantes sont en MAJUSCULES

Voir LocalDate

3.3 Variables de classes - bonnes pratiques

  • Une variable de classe mutable (non-finale):
    • ne devrait jamais être public.
    • est une variable globale, son état est imprévisible si tout le monde peut la modifier
    • pose problème dans les programmes multi-threads
    • doit être strictement contrôlée pour l’accès en écriture
    • reste en mémoire pendant toute l’exécution du programme
    • est plus difficile à tester
    • est en général déconseillée, sauf utilisation particulière
      • configuration, compteur, cache, singleton, …
  • Les constantes peuvent être public, sauf si elles ne sont utilisées que dans la classe.

3.4 Méthodes de classe

Une méthode de classe est à utiliser lorsque une méthode:

  • a un rapport avec la classe
  • n’a pas besoin des attributs de l’instance
  • ou lorsqu’elle doit accéder à des variables de classe

3.5 Méthodes de classe - Exemple 1

public record Note(double note) {
    public static Note fromString(String noteStr) {
        return new Note(Double.parseDouble(noteStr));
    }

    public static double moyenne(Note[] notes) {
        double somme = 0;
        for (int i = 0; i < notes.length; i++) {
            somme += notes[i].note;
        }
        return somme / notes.length;
    }
}

Note[] notes = { new Note(10), Note.fromString("12.5"), new Note(20) };
System.out.println(Note.moyenne(notes));

Les méthodes de classe peuvent être utilisées pour définir des constructeurs alternatifs, qui ont un nom explicite.

Voir par exemple LocalDate

3.6 Méthodes de classe - Exemple 2

Fonction pures

  • pas d’effet de bord: ne change pas de variables globales, pas d’entrées / sorties
  • déterministe: produit toujours le même résultat pour une entrée donnée
public class MathUtil {
    public static long factorielle(int n) {
        long result = 1;
        for (int i = 1; i <= n; i++) {
            result *= i;
        }
        return result;
    }
}

4 ArrayList

4.1 Déclaration

La classe ArrayList du JDK dispose d’une taille dynamique.

  • ses éléments peuvent être facilement ajoutés ou supprimés.
import java.util.ArrayList;
ArrayList<Type> arrayList = new ArrayList<>();
  • Pour les types primitifs, il faut utiliser les classes enveloppes pour qu’ils puissent être traitées comme des objets.
    • pour des entiers nous devons utiliser Integer et non int.
    ArrayList<Integer> arrayList = new ArrayList<>();
Tip

Les types primitifs int, boolean, double, … ne sont pas des objets. Pour pouvoir les traiter comme des objets, le JDK fournit des classes enveloppes (en: boxed types).

Elles ont le même nom que le type primitif correspondant mais commencent par une majuscule.

4.2 Utilisation

Méthodes courantes:

ArrayList<String> arrayList = new ArrayList<>();

// Ajout d’un élément :
arrayList.add("red");
arrayList.add("green");
arrayList.add("blue");

// Suppression d’un élément :
arrayList.remove(0);

// Accès à un élément par son indice
arrayList.get(1);

// Modification d’un élément
arrayList.set(1, "bleu");

// Longueur d’une ArrayList
arrayList.size();

4.3 Initialisation

Nous pouvons initialiser un ArrayList directement:

  • soit avec Collections.addAll
import java.util.ArrayList;
import java.util.Collections;

ArrayList<String> arrayList = new ArrayList<>();
Collections.addAll(arrayList, "Alice", "Bob", "Charlie");
  • soit avec List.of (depuis Java 9)
import java.util.ArrayList;
import java.util.List;

ArrayList<String> arrayList = new ArrayList<>(List.of("Alice", "Bob", "Charlie"));

4.4 Parcours d’un ArrayList

  • for classique avec un indice. A utiliser si on a besoin de l’indice
for (int i = 0; i < list.size(); i++) {
    System.out.println(list.get(i));
}
  • for-each. Plus simple et plus lisible
for (String name: arrayList) {
    System.out.println(name);
}
  • autres possibilités: Iterator, forEach avec Lambda (voir plus loin)

4.5 ArrayList: sous le capot

Implémentation simplifiée:

public class ArrayList<E> {
    private static final int DEFAULT_CAPACITY = 10;

    private Object[] elementData; 
    private int size;

    public ArrayList() {
        this(DEFAULT_CAPACITY);
    }

    public ArrayList(int initialCapacity) {
        if (initialCapacity > 0) {
            this.elementData = new Object[initialCapacity];
        }
    }

    public boolean add(E e) {
        if (size == elementData.length)
            elementData = grow();  
        elementData[s] = e;
        size = s + 1;
        return true;
    }

    // ... autres méthodes
}
  • La structure sous-jacente est un tableau. Lorsque la size atteint la capacité du tableau, le tableau est étendu avec grow() (recopie de tous les éléments dans un nouveau tableau plus grand).
  • Bonne pratique: si vous connaissez le nombre d’éléments, utilisez le constructeur ArrayList(int initialCapacity)
